S-01

Teoria essencial

5 conceitos que resolvem 90% do desafio
1.1 · o que é uma acl

Uma ACL (Access Control List) é a caderneta de regras na guarita. Como um porteiro que recebe instruções — "autorize o morador do 302, bloqueie o entregador de pizza do 501, quem não está na lista não entra" — a ACL diz ao roteador se cada pacote deve ser permitido ou negado com base em: origem, destino, protocolo e porta (serviço).

3 leis da ACL: ① é lida de cima para baixo, linha por linha. ② Para na primeira linha que casar com o pacote (o resto é ignorado). ③ Se ninguém casar → o pacote é negado (deny implícito).

1.4 · máscara curinga (wildcard) + calculadora

A wildcard usa 0 = "precisa ser exatamente igual" e 1 = "tanto faz". Conversão: wildcard = 255 − máscara, octeto a octeto. Atalhos: host X (um IP = 0.0.0.0) e any (tudo = 0.0.0.0 255.255.255.255).

Teste com /26, /27 e /28 — são exatamente as três redes do jogo.
1.5 · deny implícito — a regra invisível
Toda ACL termina com um deny any invisível. Se o pacote não casar com nenhuma linha, ele é barrado. Por isso a última linha escrita é quase sempre access-list 100 permit ip any any. Esquecer isso é o erro nº 1: o roteador bloqueia tudo, até o ping.
1.6 · onde aplicar: interface e direção

ip access-group 100 in|out — pense em relação ao roteador:

DireçãoSignificadoExemplo do jogo
inpacote entrando na interface (antes de rotear)tráfego do PC1 chegando pela G0/0
outpacote saindo da interface (depois de rotear)resposta do servidor saindo pela G0/0
Regra de ouro: ACL estendida → aplique o mais perto possível da ORIGEM (direção in na interface da LAN onde o PC está). Assim o tráfego ruim é barrado "logo na portaria", sem desperdiçar banda e sem atrapalhar o resto da rede.

S-03

Passo a passo

método em 6 passos — com comandos copiáveis
  1. Reconheça o terreno. Entre no roteador e veja o estado atual das interfaces.
    Router · modo usuário
    enable
show ip interface brief
  2. Configure o roteador. Hostname, endereço IP das 3 interfaces e ative cada uma.
    Router · configuração base
    configure terminal
hostname R1
interface g0/0
 ip address 172.22.34.65 255.255.255.224
 no shutdown
interface g0/1
 ip address 172.22.34.97 255.255.255.240
 no shutdown
interface g0/2
 ip address 172.22.34.1 255.255.255.192
 no shutdown
end
    Conferir: show ip interface brief → todas devem aparecer up/up.
  3. Traduza a política em regras. Leia o briefing da missão e monte a tabela no caderno: "quem não pode fazer o quê, para onde" → uma linha de ACL para cada proibição + um permit ip any any no final.
  4. Crie as ACLs (da regra mais específica para a mais genérica). Exemplo ilustrativo:
    R1(config) · ACL da rede do PC1 — exemplo
    configure terminal
access-list 100 deny tcp host 172.22.34.66 host 172.22.34.62 eq ftp
access-list 100 deny tcp host 172.22.34.66 host 172.22.34.62 eq telnet
access-list 100 permit ip any any
end
  5. Aplique a ACL na interface de entrada da rede de origem, direção in:
    R1(config) · aplicar na interface
    interface g0/0
 ip access-group 100 in
end
  6. Teste e ajuste. Nas abas PC1/PC2 do jogo, e depois no roteador:
    PC1 / PC2 · testes
    ipconfig
ping 172.22.34.62
ftp 172.22.34.62
telnet 172.22.34.62
browser 172.22.34.62
    R1# · verificação
    show access-lists
show ip interface g0/0
show running-config
    💡 show access-lists mostra os contadores de match — se a linha errada tem hits, é ela a culpada! Para reescrever uma ACL numerada: no access-list 100 apaga a lista inteira → recrie do zero.

S-05

Prova de fogo & erros clássicos

como testar como um profissional
sintoma → causa
SintomaCausa provável
Tudo parou (até o ping)Faltou o permit ip any any — o deny implícito barrou tudo
O bloqueio não aconteceDireção errada (in/out), interface errada, ou ACL criada mas não aplicada
Bloqueia mais do que deviaOrdem errada: um permit genérico antes do deny específico (a ACL para no 1º match!)
Nenhuma resposta de nadaInterface sem IP ou esqueceu o no shutdown
Modifiquei a ACL e nada mudouACL numerada só se edita apagando: no access-list 100 + recriar
método do detetive (para o caso final)
  1. Rode todos os testes em PC1 e PC2. Anote: o que deveria acontecer × o que aconteceu.
  2. show access-lists → encontre a linha cujo contador de matches dispara nos testes que falham.
  3. show ip interface g0/x → confira onde (interface/direção) cada ACL está aplicada.
  4. Acuse a linha correta no caso e feche a operação. 🕵️
No Packet Tracer real, use o modo Simulation para assistir o pacote sendo barrado na interface — visualiza exatamente a direção in/out.
